# Release Cleanup Checklist — v3.0.1 Launch

> **FOR MAINTAINER USE ONLY — do not automate.**
> Work through this list on the GitHub Releases page before uploading fixed builds.

---

## Step 1 — Delete broken / outdated assets from GitHub Releases

Go to: **https://github.com/Roopesh-kosuri/code-os/releases**

### v3.0.0 — delete ALL installer assets (broken: show "install Python" on fresh machines)

Log in, click **Edit** on the v3.0.0 release, then delete the following files:

- [ ] `CODE-OS-Setup-3.0.0.exe` (NSIS installer — missing bundled binary)
- [ ] `CODE-OS-3.0.0-portable.exe` (portable — missing bundled binary)
- [ ] `CODE-OS-3.0.0.dmg` (macOS DMG — missing bundled binary)
- [ ] `CODE-OS-3.0.0-mac.zip` (macOS ZIP — missing bundled binary)
- [ ] `CODE-OS-3.0.0.AppImage` (Linux AppImage — missing bundled binary)
- [ ] `code-os_3.0.0_amd64.deb` (Linux deb — missing bundled binary)
- [ ] `builder-debug.yml` (internal electron-builder debug file — should never be uploaded)
- [ ] Any `*.blockmap` files

> Keep: the **Source code (zip)** and **Source code (tar.gz)** auto-generated by GitHub — these are always correct.

### v2.4.0 — delete ALL assets (superseded release)

Click **Edit** on the v2.4.0 release (or **Delete release** if you want to remove it entirely), then delete:

- [ ] `CODE.OS.Setup.2.4.0.exe`
- [ ] `CODE.OS-2.4.0-portable.exe`
- [ ] `CODE-OS-2.4.0.AppImage`
- [ ] `code-os_2.4.0_amd64.deb`
- [ ] `code-os-2.4.0.tar.gz`
- [ ] `builder-debug.yml`
- [ ] Any `*.blockmap` files

> Keep or delete the entire v2.4.0 release at your discretion. If you keep it, leave only the GitHub-generated source archives.

---

## Step 2 — Build fixed installers locally

Follow the instructions in [CONTRIBUTING.md → Manual Release Procedure](../CONTRIBUTING.md).

| Platform | Build machine | Command |
|----------|--------------|---------|
| macOS    | CI (automatic) | Pushed by `release.yml` on tag push |
| Windows  | Windows machine | `npm run package` |
| Linux    | Ubuntu 22.04 / WSL2 | `npm run package` |

Verify each binary on a **clean machine** (no Python, no Node pre-installed) before uploading.

---

## Step 3 — Create (or edit) the v3.0.1 release on GitHub

1. Push tag: `git tag v3.0.1 && git push origin v3.0.1`
2. CI will auto-build and upload macOS assets (`.dmg` + `.zip`).
3. Upload Windows and Linux assets manually.

### Exact asset filenames to upload for v3.0.1

| Asset | Source path |
|-------|------------|
| `CODE-OS-Setup-3.0.1.exe` | `release/CODE-OS-Setup-3.0.1.exe` |
| `CODE-OS-3.0.1-portable.exe` | `release/CODE-OS-3.0.1-portable.exe` |
| `CODE-OS-3.0.1.AppImage` | `release/CODE-OS-3.0.1.AppImage` |
| `code-os_3.0.1_amd64.deb` | `release/code-os_3.0.1_amd64.deb` |
| *(macOS uploaded by CI automatically)* | `release/CODE-OS-3.0.1.dmg`, `release/CODE-OS-3.0.1-mac.zip` |

> **Do not** upload `builder-debug.yml`, `*.blockmap`, or `*.yml` metadata files.

---

## Step 4 — Verify downloads on clean machines

- [ ] Windows: download `CODE-OS-Setup-3.0.1.exe`, install on a machine with NO Python, NO Node. App must start and backend must connect within 30 s.
- [ ] macOS: download `.dmg`, mount, run. App must start on a fresh macOS with no developer tools.
- [ ] Linux: download `.AppImage`, `chmod +x`, run. App must start without any system Python.
